## 🐛 修复模式分析

- 修复/功能比: 2/8（约 25%），低于 40% 警戒线。
- 明确修复类提交：
  - `fix(frontend): 修复登录API路径拼接并切换Vercel转发域名`
  - `feat(backend): 集成 Cloudflare R2 存储并修复类型契约`（功能提交中包含修复）
- 摩擦日志显示的实际修复类型：
  - API 基址与 `/api/v1` 路径重复风险。
  - Render/Vercel 环境变量与域名不一致。
  - Vercel 部署缓存导致入口文件与 chunk 版本不一致。
  - PageIndex worker/web service 健康检查语义混淆。

**判断**: commit 层面的 fix 比例健康，但环境链路类问题一次耗时较高（150 分钟 + 45 分钟），应优先优化“部署/健康检查/环境变量核对”流程，而不是单纯增加业务测试。
